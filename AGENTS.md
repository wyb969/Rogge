# ROGGE development rules

- Read `docs/AI_HANDOFF.md` before changing the project. Check the actual branch, worktree and `git status`; the default branch may lag gameplay development. Code and reproducible evidence take precedence over old conversation summaries.
- Use Godot 4.7 and matching export templates. Give export commands an explicit output path; the preset paths came from an older machine. Native checks use `gl_compatibility`; do not assume the project configuration already selects it.
- Preserve existing asset paths, scene names, `.uid` files and meaningful `.import` settings. Historical spellings such as `assest/`, `pasue_menu.gd` and `PasueMenu.tscn` are referenced by the project. Avoid broad renames or formatting of recovered scripts.
- `main.gd` owns menus and creates a fresh `game.tscn` per run. `game.gd` owns run state and controllers; `spawner.gd` owns encounter progression. Regular horde enemies use `enemy_shell.gd`, not necessarily the legacy `enemy.gd`.
- Integrate cards through the draft pool, game dispatch, controller, equipment display, rank caps, lottery rewards and run/transition cleanup. Debug equipment must not leak into a normal run.
- Route combat through the existing damage/death APIs. Preserve speed-trial vulnerability, Boss warning/attack alignment and kill rewards. Guardian entry pauses new waves but retains existing minions; keep defeat/rest/transition cleanup separate. Timed damage uses the existing `from_status` contract to avoid recursive procs. Reserve `damage_is_final` for already computed internal damage; never apply modifiers twice.
- Enemy death signals fire after removal from `EnemyGroup`. Kill-triggered rewards should validate the actual death/type and deduplicate within a bounded buffer; do not require live-group membership at that point.
- Ordinary enemy attack variants compose through `EnemyData.attack_style` and `tactical_enemy_ai.gd`. Remote variants retain `Archetype.RANGED` to share spawn caps. `EnemyAttackField` owns pooled warnings/projectiles; preserve locked geometry, once-only hits and source-death/control cancellation.
- Reuse bounded buffers and effects. `CombatTargets` is a registry with linear queries, not a spatial index. Avoid scene-tree searches per target, unbounded particle/light nodes and nested crowd scans. Weather particles that represent the world must remain in world coordinates.
- Keep Debug paginated with fixed navigation. Size mobile touch targets in displayed pixels using the viewport transform and Web canvas CSS/device-pixel ratio; avoid text/hover expansion. Removing UI entries must not break callable regression presets.
- Respect pause, rest, trial, death and return-to-menu states. Clear transient effects and force states without discarding owned card ranks between stages. Release temporary movement locks on trial success/failure, end_game and new runs.
- Keep hostile attacks, pickups, healing and status colors distinguishable. Tooltips use the project TooltipLabel theme with bundled CJK fallback; a font override on the hovered icon alone does not style its popup. Favor short audio cues, separate audio buses and bounded local lighting over continuous noise or full-screen glow. Mobile Safari is an important performance target.
- The selected visual style is the Cursor palette from `cursor/color-palette-v4-4455`: `GamePalette` plus shared `body_tint.gdshader`, original weapon/coin/icon textures, purple poison and neutral controls. Older palette-readability/v4 color rules are historical. Do not reintroduce the removed semantic-ramp recoloring or global GameUiTheme; current UI/feedback aliases must resolve to the same Cursor palette. Check color and grayscale views.
- `coin.gd` is the existing gold coin that grants experience, not a separate currency system. Preserve its original gold art and XP/reward logic. Floors use the Cursor stage table: fixed teal-moss opening and distinct later colors/vignettes. Keep source-style shared lighting and bounded effects; avoid a second body/ground recoloring layer. Winter snow is a weather-weighted surface effect: preserve the underlying stage tint and world-space flakes/tracks.
- Upgrade copy comes from read-only `CardPreview` and `CardNumbers`, using the same stat helpers as live upgrades. Keep actual current→next values and character-level/combo modifiers in tooltip/Codex; never change balance to match old copy. The speed card remains fixed +20. Draft choices must all fit on one screen: three compact columns in both orientations with outer/inter-card spacing; icon above two tight lines (name, function plus actual next value). No scroll or Details buttons; preserve hover enter/exit scaling. Keep full descriptions in the separate Codex.
- Player gait uses displacement after `move_and_slide`, with two side-facing animations, neutral idle/wall/lock poses and no walking emitter. Keep 360-degree movement/dash and the last-movement idle dash separate from sprite facing. Camera follow has one bounded world-position spring; do not stack built-in Camera2D smoothing or drive follow from intended velocity. Cosmetic deformation must not change colliders.
- Attach player-local meters to Player, outside the deforming sprite. Render pooled projectile arcs between completed physics ages on every display frame; keep fuses, hit geometry, damage and cooldowns in physics. Dash afterimages sample actual traveled distance and stay within the shared fixed pool.
- Combat hitstop has one owner in HitFeedback with real-time deadlines, nonextending cooldowns and a fixed silhouette pool. Restore only its own time scale; preserve death slow-motion and timed-trial windows. Periodic/from_status damage and blocked player damage must not start stops. Keep flashes separate from body materials/status tint; popup/stain fades use unscaled time.
- Run focused smoke tests for the changed subsystem and required import/export checks. Broaden testing for shared combat/lifecycle changes or an unresolved failure; do not run the whole suite for documentation-only edits. Distinguish native tests, packed-resource tests and real browser/device play.
- Preserve user edits and untracked files. Do not clean/reset worktrees, overwrite user files or force-push as routine work. Keep completed source and handoff notes in Git; temporary cloud paths and chat history are not durable storage.
- Keep credentials in environment secrets, never source, documents or logs. Publish only within the user's requested scope. Updating the existing itch build channel, editing its storefront and verifying a live browser session are separate operations; report which actually completed.
- Update `docs/AI_HANDOFF.md` after material changes with code checkpoints, evidence, remaining issues and next steps. Do not describe an old test report as a fresh run or a suspected cause as a confirmed diagnosis.

- Wind and ice are gameplay environments independent of cosmetic weather intensity. Keep ice terrain identifiable with FX off, use bounded target velocities, and snapshot any attack distance modifier together with its warning; never add untelegraphed landing drift. Preserve pause/trial/movement-lock priority.

- Stage-selected electric terrain owns a separate actor stun timer; do not reuse trial movement locks or global hitstop. Snapshot conduction before damage, deduplicate across all terrain zones per pulse and preserve per-target cooldowns, cancel stale attack geometry, and preserve the player's electrical escape grace.

- Terrain knockback has its own collision-aware impulse state. Cancel stale attack geometry before displacement, preserve trial lock priority and dash immunity, and clear only terrain-owned impulses on lifecycle exits. Mine respawn is timed from contact, not from visual completion.

- Terrain airborne feedback is cosmetic Z, separate from ground collision/control duration. Keep foot locators and contact shadows on the ground, move attached weapon art with the body, and retain cleanup ownership until landing finishes. Route launch/landing shake through the existing camera mixer.

- Each stage owns one cached hazard selected independently from weather (mines/electric/spikes). Debug overrides are explicit; changing weather must not reroll hazards. Electric skeleton replacement restores prior body/weapon visibility on expiration and lifecycle exits, without overwriting material/status tint.

- Wind trails target Web/Compatibility: use the bounded world-space particle-history ribbon pool, not unsupported GPU trail rendering. Keep cosmetic flow independent of gameplay wind and combat RNG; advance at bounded fixed steps with render interpolation and clear histories on lifecycle exits.

- Player-facing text uses `locale/messages.csv` and `L10n`/TranslationServer (English default, zh_CN optional). Translate templates before formatting, not IDs/actions/audio buses. Keep CardNumbers stat keys/formulas stable, maintain English aliases for live static UI translation, and run the localization audit plus focused UI checks. Import CSV before Web export; short upgrade cards keep common physical dimensions and large icons in both languages; full descriptions and stat rows stay reachable through the Codex.

- `SessionMenu` owns nested pause snapshots: returning from settings/Codex must restore the prior paused state, focus and touch-control visibility, including pending cards/rest/trials. Codex reads shared equipment metadata, trial rules and CardPreview only; never roll drafts, apply upgrades, reset trials or consume gameplay RNG while browsing or translating.

- Stage bosses tick shared control once per physics frame: 3 continuous controlled seconds grant 3 seconds of control immunity, not damage immunity. Wind role paths must tick it and release cancelled attack ownership. Attack cancellation clears warnings only; hide/disable Boss HUDs only on defeat/suspend. Use shared boss_hud_layout for readable, separated bars.
