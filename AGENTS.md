# ROGGE development rules

- Read `docs/AI_HANDOFF.md` before changing the project. Check the actual branch, worktree and `git status`; the default branch may lag gameplay development. Code and reproducible evidence take precedence over old conversation summaries.
- Use Godot 4.7 and matching export templates. Give export commands an explicit output path; the preset paths came from an older machine. Native checks use `gl_compatibility`; do not assume the project configuration already selects it.
- Preserve existing asset paths, scene names, `.uid` files and meaningful `.import` settings. Historical spellings such as `assest/`, `pasue_menu.gd` and `PasueMenu.tscn` are referenced by the project. Avoid broad renames or formatting of recovered scripts.
- `main.gd` owns menus and creates a fresh `game.tscn` per run. `game.gd` owns run state and controllers; `spawner.gd` owns encounter progression. Regular horde enemies use `enemy_shell.gd`, not necessarily the legacy `enemy.gd`.
- Integrate cards through the draft pool, game dispatch, controller, equipment display, rank caps, lottery rewards and run/transition cleanup. Debug equipment must not leak into a normal run.
- Route combat through the existing damage/death APIs. Preserve speed-trial vulnerability, Boss warning/attack alignment and kill rewards. Guardian entry pauses new waves but retains existing minions; keep defeat/rest/transition cleanup separate. Timed damage uses the existing `from_status` contract to avoid recursive procs. Reserve `damage_is_final` for already computed internal damage; never apply modifiers twice.
- Ordinary enemy attack variants compose through `EnemyData.attack_style` and `tactical_enemy_ai.gd`. Remote variants retain `Archetype.RANGED` to share spawn caps. `EnemyAttackField` owns pooled warnings/projectiles; preserve locked geometry, once-only hits and source-death/control cancellation.
- Reuse bounded buffers and effects. `CombatTargets` is a registry with linear queries, not a spatial index. Avoid scene-tree searches per target, unbounded particle/light nodes and nested crowd scans. Weather particles that represent the world must remain in world coordinates.
- Keep Debug paginated with fixed navigation. Size mobile touch targets in displayed pixels using the viewport transform and Web canvas CSS/device-pixel ratio; avoid text/hover expansion. Removing UI entries must not break callable regression presets.
- Respect pause, rest, trial, death and return-to-menu states. Clear transient effects and force states without discarding owned card ranks between stages. Release temporary movement locks on trial success/failure, end_game and new runs.
- Keep hostile attacks, pickups, healing and status colors distinguishable. Tooltips use the project TooltipLabel theme with bundled CJK fallback; a font override on the hovered icon alone does not style its popup. Favor short audio cues, separate audio buses and bounded local lighting over continuous noise or full-screen glow. Mobile Safari is an important performance target.
- Use `GamePalette` v4 for runtime colors and shader uniforms: cyan player/friendly attacks, red/orange enemies and red warnings, purple poison, green beneficial pickups/healing, gold coins/shields, neutral controls. Functional skill borders may use the named heal/lightning/cooldown/shield accents. Shared ramp materials must not be mutated per actor; verify color and grayscale views.
- `coin.gd` is the existing gold coin that grants experience, not a separate currency system. Preserve its gold appearance and XP/reward logic; use pickup green for distinct beneficial pickups. Stage-one floors use teal moss variants, followed by warm earth and dark violet families. Ground shadows are black translucent ellipses with bounded cached sources.
- Upgrade copy comes from read-only `CardPreview` and `CardNumbers`, using the same stat helpers as live upgrades. Show actual current→next values, character-level and combo modifiers; never change balance to match old copy. The speed card remains fixed +20. Keep mobile draft scrolling separate from selection on release.
- Run focused smoke tests for the changed subsystem and required import/export checks. Broaden testing for shared combat/lifecycle changes or an unresolved failure; do not run the whole suite for documentation-only edits. Distinguish native tests, packed-resource tests and real browser/device play.
- Preserve user edits and untracked files. Do not clean/reset worktrees, overwrite user files or force-push as routine work. Keep completed source and handoff notes in Git; temporary cloud paths and chat history are not durable storage.
- Keep credentials in environment secrets, never source, documents or logs. Publish only within the user's requested scope. Updating the existing itch build channel, editing its storefront and verifying a live browser session are separate operations; report which actually completed.
- Update `docs/AI_HANDOFF.md` after material changes with code checkpoints, evidence, remaining issues and next steps. Do not describe an old test report as a fresh run or a suspected cause as a confirmed diagnosis.
